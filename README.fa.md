![نمای گفت‌وگوی دانشیار](docs/screenshots/chat.png)

دانشیار یک پروژه کامل RAG و قابل اجراست. فایل PDF، ورد، Markdown یا متن را
می‌گیرد، محتوایش را پردازش و نمایه‌سازی می‌کند و به پرسش‌های فارسی یا انگلیسی
با ذکر نام سند، شماره صفحه و متن شاهد پاسخ می‌دهد.

هدف پروژه فقط ساختن یک «چت با PDF» دیگر نبود. مسئله اصلی این بود که کاربر
بتواند هر ادعای پاسخ را بررسی کند و بداند مدل دقیقاً از کدام بخش سند استفاده
کرده است.

## قابلیت‌ها

- بازیابی ترکیبی معنایی و کلیدواژه‌ای با Weighted RRF
- پشتیبانی واقعی از متن فارسی و یکسان‌سازی حروف عربی و فارسی
- نمایش منبع، شماره صفحه، درصد ارتباط و قطعه متن بازیابی‌شده
- پاسخ جریانی و زنده از مدل محلی Ollama
- مدیریت فایل‌ها، وضعیت پردازش و حذف کامل سند از همه لایه‌ها
- تاریخچه گفت‌وگو و ذخیره استنادهای هر پاسخ
- تشخیص فایل تکراری با SHA-256
- رابط کاملاً راست‌به‌چپ، واکنش‌گرا و دارای پوسته روشن و تیره
- تست آفلاین، داده نمونه، ارزیابی بازیابی، Docker و GitHub Actions
- حالت دمو بدون دانلود مدل برای بررسی سریع کل فرایند

## اجرای سریع در ویندوز

پیش‌نیازها: Python 3.11 یا 3.12، Node.js 20.19 به بالا، Git و Ollama.

    git clone https://github.com/Abouzarsh/daaneshyar-rag.git
    cd daaneshyar-rag
    Copy-Item .env.example .env
    .\scripts\setup.ps1
    ollama pull qwen3:4b
    ollama pull embeddinggemma
    .\scripts\run-dev.ps1

سپس http://localhost:5173 را باز کنید. مستندات تعاملی API نیز در
http://localhost:8000/docs در دسترس است.

برای بارگذاری فایل‌های نمونه:

    python scripts/seed_demo.py

## اجرای Docker

ابتدا Ollama باید روی ویندوز در حال اجرا باشد:

    Copy-Item .env.example .env
    docker compose up --build

رابط برنامه در http://localhost:3000 باز می‌شود.

## حالت دمو بدون مدل

اگر فقط می‌خواهید رابط و مسیر کامل برنامه را بدون دانلود مدل ببینید، در فایل
.env مقدار زیر را قرار دهید:

    RAG_DEMO_MODE=true

در این حالت یک Embedding قطعی و سبک، حافظه برداری موقت و پاسخ‌دهنده آزمایشی
فعال می‌شود. این حالت برای توسعه و تست مناسب است، نه سنجش کیفیت معنایی.

## چرا هم Qdrant و هم FTS5؟

جست‌وجوی معنایی مفهوم‌های مشابه را پیدا می‌کند، اما ممکن است در نام تجهیز،
کد خطا یا عبارت دقیق ضعیف‌تر باشد. FTS5 همان عبارت‌های دقیق را خوب پیدا می‌کند.
دانشیار رتبه‌های هر دو مسیر را با RRF ترکیب می‌کند؛ در نتیجه هم مفهوم پرسش و
هم واژه‌های مهم آن در نتیجه اثر دارند.

## محدودیت‌های آگاهانه

- نسخه اول OCR داخلی ندارد و PDF اسکن‌شده باید پیش از آپلود OCR شود.
- صف پردازش درون همان فرایند API اجرا می‌شود؛ برای مقیاس سازمانی باید یک صف
  پایدار اضافه شود.
- پروژه برای یک کاربر محلی طراحی شده و احراز هویت چندکاربره ندارد.
- ارزیابی همراه پروژه، بازیابی منبع صحیح را می‌سنجد و ادعای امتیاز کامل کیفیت
  پاسخ ندارد.

این محدودیت‌ها پنهان نشده‌اند، چون بخشی از مهندسی خوب، مشخص‌کردن مرز واقعی
محصول است.
