# سناریوی دمو برای ویدئو یا ارائه

یک دموی خوب بهتر است ۲ تا ۳ دقیقه باشد و به‌جای فهرست‌کردن فناوری‌ها، مسئله را
حل کند.

## آماده‌سازی

1. برنامه و Ollama را اجرا کنید.
2. دستور python scripts/seed_demo.py را بزنید.
3. صبر کنید هر سه سند وضعیت «آماده پرسش» بگیرند.
4. مرورگر را روی اندازه 1440×900 قرار دهید.
5. از نمایش فایل‌های شخصی، کلید API یا مسیرهای سیستم خودداری کنید.

## متن پیشنهادی اجرا

«این دانشیار است؛ یک دستیار RAG فارسی که جواب را فقط از اسنادی که به آن
می‌دهیم می‌سازد. تفاوت اصلی‌اش این است که کنار هر جواب، سند و متن واقعی مورد
استفاده را هم نشان می‌دهد.»

در صفحه اسناد، فایل راهنمای عملیات شبکه را نشان دهید و بگویید:

«فایل بعد از آپلود استخراج، قطعه‌بندی و هم‌زمان در جست‌وجوی معنایی و
کلیدواژه‌ای نمایه می‌شود.»

سپس این سؤال را بپرسید:

    در رخداد P1 زمان پذیرش و هدف بازگردانی اولیه سرویس چقدر است؟

بعد از پاسخ، منبع اول را باز کنید:

«این قسمت مهم است: می‌توانم متن شاهد را ببینم و ادعای مدل را همان لحظه بررسی
کنم. نام فایل، روش بازیابی و میزان ارتباط هم مشخص است.»

برای نشان‌دادن پشتیبانی دو‌زبانه بپرسید:

    When must a support case be escalated?

در پایان، صفحه درباره سامانه را باز کنید:

«Backend با FastAPI، ذخیره برداری با Qdrant، جست‌وجوی دقیق با FTS5 و مدل محلی
با Ollama اجرا می‌شود. هسته بازیابی را خودم پیاده‌سازی کرده‌ام تا منطق سیستم
شفاف و قابل تست باشد.»

## شات‌های مناسب برای نمونه‌کار

- صفحه خالی گفت‌وگو با سه پیشنهاد آماده
- پاسخ فارسی همراه با دو کارت منبع بازشده
- صفحه کتابخانه با سه سند آماده
- نمای Swagger از endpoint جریانی
- خروجی سبز تست‌ها در ترمینال

## چیزهایی که در دمو نگویید

- ادعای دقت ۱۰۰ درصد
- ادعای مناسب‌بودن برای تولید سازمانی بدون احراز هویت
- مقایسه سرعت بدون اجرای Benchmark واقعی
- معرفی داده‌های نمونه به‌عنوان داده واقعی شرکت
